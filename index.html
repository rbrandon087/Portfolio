Apex Legends Status API

What I built

  • A four-table relational schema with foreign keys: users, rank snapshots, legend stats, and guilds.
  • An Express API that is the only path to the database, so the bot and poller never touch it directly.
  • A poller that saves a rank snapshot for every player every 15 minutes, so history builds with no gaps.
  • Slash commands /register and /rank, with deferred replies to beat Discord's 3-second limit.

Key design decisions

  • Players are stored by permanent Apex UID, because display names change.
  • Each player lookup runs in its own try/catch, so one failure never stops the poll.
  • Every query is parameterized. That fixed a real bug where a template literal saved the text "null" instead of SQL NULL.

Discord AI Bot

A private game research assistant. Ask it about quests, weapons, or game info in a DM and it searches the web and answers, remembering the conversation.

What I built

  • A Discord bot that answers only in direct messages and ignores its own messages.
  • An async OpenAI integration with the web search tool, so answers use current game info, not just what the model was trained on.
  • Per-user conversation memory, so follow-up questions like "what's the next step?" make sense.
  • A typing indicator while the answer is generated.

Key design decisions

  • Memory stores one previous_response_id per user instead of resending the whole chat history every time.
  • Long answers are split into 2,000-character chunks, because Discord rejects longer messages.
  • I used the async OpenAI client so waiting on an answer doesn't freeze the bot.
  • API keys live in .env, which is kept out of the repo by .gitignore.

Hollowmere: The Narrator Awakens In progress

An AI Dungeon Master text adventure. Build a character, roll real dice, and an AI narrator runs a spooky, detailed story that's saved to a database as you play.

Working now

  • Character creation with 10 races, 13 classes, 10 backgrounds or a custom one, and six ability scores rolled 4d6-drop-lowest.
  • Starting equipment by class, all of it known to the narrator along with race, class, background, and scores.
  • A roll command: the narrator asks for a d20 on risky actions and narrates the result from a fixed table, from disaster on a 1 to extraordinary on a 20.
  • A PostgreSQL database with seven tables. Every turn, roll, and item is saved, and adventures can be loaded, deleted, or restarted.
  • The start of a Flask web app, with Google sign-in registered through Authlib.

Key design decisions

  • Dice are rolled in code, never by the AI, so results are truly random and can't be bent to fit the story.
  • The story is saved one row per turn instead of as one big JSON blob, so saving a turn never rewrites the whole story.
  • Deleting an adventure clears its turns, rolls, and equipment first, so foreign keys never leave orphaned rows.
  • Strict narrator rules: it never acts for the player, never describes their feelings, and never hands them items they didn't find.

Coming next

  • Finish Google sign-in and move the game into the browser, with a dark medieval look.
  • Multiplayer parties, save slots, and dice roll history.
